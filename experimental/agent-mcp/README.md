# Experimental Weftline agent MCP

By default, this stdio MCP server exposes only the **read-only** `discover` and `resolve` tools using the existing review-v1 connector. It does not launch or execute work. Experimental claim and submit tools require explicit opt-in and a separately enabled local listener; see [WRITE-EXPERIMENT.md](WRITE-EXPERIMENT.md) for their restrictions. Discovery is partial and non-snapshot; a task's state remains unknown and any observed version is not necessarily current. A missing result is not proof of absence or authorization to work.

Both read tools accept an optional integer `guardGeneration` (0–999998); when omitted, the startup `--guard` is used. Supply a guard independently established as current after an operation advances it; the adapter neither discovers nor updates the guard automatically. A recorded receipt is historical evidence, not proof of the current guard. Restart pagination without a continuation when changing guards: continuations are bound to the guard that issued them.

The default mode requires a separately running, direct-TLS, loopback review-v1 listener and the connector's explicit `--enable`, `--endpoint`, `--ca`, `--actor`, `--board` and `--guard` arguments. An experimental `--remote-https` mode accepts a canonical HTTPS origin and checks the hostname against the supplied CA. One explicitly approved, supervised read-only Hermes discovery against the isolated live tester succeeded on 2026-11-20; the session was revoked and independently verified absent. This does not establish persistent access or authorize general real-session use. In either mode the configured authority and CA must be trusted; redirects are rejected. The Appwrite session for that actor is supplied privately in the `WEFTLINE_AGENT_SESSION` process environment, never as an MCP tool argument. Do not put real session values in source files, command lines, logs, prompts, examples or project notes. Use a separately approved secret-provisioning mechanism for each client and actor; the process and other same-user processes remain in the trust boundary. Deleting a Node environment property does not remove the initial process environment from the operating system. Session issuance, refresh, expiry and revocation are not implemented here.

For the listener, `WEFTLINE_REVIEW_READ_ONLY=1` enables a separate direct-loopback mode that accepts only the discovery and resolution routes. It rejects proxy mode and all UI, authentication and knowledge feature switches, as well as mutation routes. It does not make the Appwrite key read-only, fence other processes, prove exclusive writers, or authorize use with real data. The mode is experimental and independently reviewed before real use; without the flag the listener retains its existing mutation routes.

Install the isolated experiment's dependencies with `pnpm --dir experimental/agent-mcp install --frozen-lockfile --ignore-scripts`. Run the synthetic integration tests from the repository root with `node --test experimental/agent-mcp/test/agent-mcp.test.js`. Optional platform probes require `WEFTLINE_HERMES_SOURCE_DIR` for the installed Hermes source and `WEFTLINE_CODEX_LIVE_PROBE=1` for a real Codex client/model invocation; the latter can incur usage. Tests create disposable local certificates and use an in-process synthetic provider and sessions. The fixture observed no provider writes through its intercepted fetch path; this is not an OS-level network or filesystem isolation guarantee. The optional Codex probe uses the already authenticated local Codex account and an in-memory configuration override; it does not register or modify the user's MCP configuration. The Hermes probe uses a temporary isolated home. Neither establishes live Appwrite authorization, a deployed connector, T3 Code compatibility, automatic pickup or safe external effects.

An isolated T3 Code 0.1.6 server with a synthetic process-wide Codex override also invoked `discover` successfully; its persisted tool event contained the synthetic result. This was a disposable test instance in full-access mode, not proof of confinement, configuration of the shared T3 server, other T3 providers, or real Appwrite access.

Each MCP connection runs as the configured actor with its supplied session: a local process isolation boundary or the MCP protocol does not create independent credentials per caller. Before real use, independently provision and verify per-actor sessions, protect session handoff, review the complete transport and host security, and verify effective permissions and revocation. Do not enable automatic execution or connect to private real data on the basis of synthetic tests.

The per-process limit of four bounds connector calls, not all protocol requests. If Node's stdout queue exceeds 65,536 bytes before a response, the process terminates with status 73; queued replies may be lost. A synthetic non-reading flood test and 100 sequential requests from a reading client exercise this boundary, not a general load, liveness or memory guarantee. An individual response and other buffers can exceed that threshold; there is no protocol-wide admission limit or write deadline. Do not use this adapter with an untrusted or unattended client. Generic errors are tested for rejected tool names and argument keys; malformed protocol traffic and every SDK-generated error have not been exhaustively verified.

The SDK's 65,536-byte input buffer is checked before individual messages are split, so a sufficiently large pipelined chunk of individually valid messages may disconnect the client. Clients should avoid large bursts; this compatibility limit has not been load-tested. JSON-RPC request IDs are echoed for correlation and must not contain secrets. Protocol error diagnostics are deliberately replaced with a generic message.
